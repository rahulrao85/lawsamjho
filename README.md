# LawSamjho

Read a legal document before you sign it.

LawSamjho takes a document you already have, splits it into numbered clauses,
and then answers about it in plain language — with every generated claim tied
back to the clause it came from.

**This is not legal advice and does not replace a lawyer.** The point of the
tool is to make you a better-informed person in the room, not to remove the
lawyer from it.

## The core design rule

> Never let the model do what deterministic code can do.

1. Segmentation into stable clause IDs (`CLAUSE-01`, `CLAUSE-02`, …) is plain
   code. It happens **before** any model call, so every downstream feature
   shares one vocabulary of citable IDs.
2. The model is only ever asked to do language work, and only ever through a
   strict Zod schema. Output that fails validation is a failed generation —
   retried once, then surfaced as an error. Unvalidated output is never
   rendered.
3. Every clause ID a model returns is checked against the real segmentation.
   Invented IDs are dropped silently. Deadlines are computed by date
   arithmetic, never generated by the model.

That third point is what separates a grounded tool from a chat wrapper, and it
is what makes the "not legal advice" framing honest rather than decorative.

### What the pipeline actually does

```
upload (PDF or .txt)
   │  lib/upload.ts        extension + MIME + %PDF- magic bytes + size
   │  lib/pdf/extract.ts   unpdf text layer; a scan comes back empty and is refused
   ▼
segment (lib/segment.ts)  deterministic → PREAMBLE + CLAUSE-01..nn
   ▼
one structured model call (lib/summary/generate.ts)
   │  summary sentences · key terms · risks · obligations · key dates
   ▼
two gates
   │  citation gate (lib/summary/verify.ts)
   │    canonicalise ("clause 3", "#3", "CLAUSE-003") → "CLAUSE-03"
   │    drop anything that does not match a real clause ID
   │    drop any whole sentence left with no surviving citation
   │  quote gate (lib/summary/quote.ts)
   │    every deadline's quoted words must appear in the clause it cites,
   │    in order — otherwise the quote is discarded and no date is computed
   ▼
render (components/simplify/*) — every claim click-through to its clause
   │  deadlines arrive as a stated offset, never as a date
   ▼
deadline arithmetic (lib/deadlines.ts)
      computed in the browser from the anchor date the user picks
```

Nothing the model returns is rendered before the gates have run, and both gates'
counts are displayed rather than hidden: a filter nobody can see is
indistinguishable from no filter at all.

### The one rule about dates
**The model is never asked to work out a date, and never produces one.** It
reports two things and stops:

- `deadlineQuotedText` — the deadline in the document's own words, e.g.
  `"within ninety (90) days of the Licensee vacating the Premises"`, verified
  against the clause before it is shown; and
- the offset it describes — `90`, `days`, `after`, `event`.

`lib/deadlines.ts` then turns that into a calendar date, in UTC, with month-end
clamping (31-Jan + 1 month is 28-Feb, not 2-Mar — `Date.UTC` silently overflows
and would put a notice deadline three days late).

A model asked to compute "6 months after 01-Apr-2026" is right most of the time,
and the time it is wrong it is wrong confidently, on a date somebody might rely
on. That trade is not worth taking, so it is not taken.

Four deadline bases are tracked, because "no date" has four different causes and
they should not read the same on screen:

| Basis | Meaning | Date computed? |
|---|---|---|
| `anchor` | runs from the agreement/signing date | yes |
| `event` | runs from something that has not happened (vacating, a default) | no |
| `recurring` | repeats (rent by the 7th of every month) | no — there is no single date |
| `none` | the clause states no deadline | no |

### Grounded Q&A

Ask a question and the answer is drawn only from the clauses you already have —
no re-upload, because the browser kept them. Two things make it grounded rather
than a chat wrapper:

**All-or-nothing citations.** A summary with one weak sentence can drop that
sentence. An answer cannot: the citation *is* the evidence, so removing a bad
one would leave a plausible answer whose support is partly fabricated. If any
cited clause does not exist, the whole generation is rejected and retried, and if
it never passes, the user is told plainly rather than shown something
unsupported.

**"Not in the document" is an answer, not an error.** When the clauses do not
cover a question the model says so, and the message the user reads is composed
by the server — the model's own prose is discarded for that status, so there is
no unverifiable sentence on screen. Questions like "what is the capital of
France" get that treatment rather than a guess.

### Prompt injection

Two layers, deliberately unequal:

1. **A pattern screen on the question** (`lib/injection.ts`) over a normalised
   copy — NFKC-folded, stripped of zero-width and bidi characters, whitespace
   collapsed — because the usual evasions are typographic rather than clever.
   It blocks the explicit "ignore your instructions" family and does not try to
   detect *topics*: "what happens if I ignore the notice clause?" is a question
   about the document and must pass.
2. **The structure of the prompt**, which is the real defence. Clauses and the
   question each arrive inside an explicit `<<<CLAUSES` / `<<<QUESTION`
   delimiter, and the system prompt states that everything inside them is data
   to be interpreted, never an instruction to follow.

A blocked question costs nothing — it never reaches the model, and the user gets
a reason rather than a vague failure. There is no separate topic-gate model call.

### The lawyer-prep brief

One artifact to take to a lawyer: the situation, what the document requires,
where it works against the reader, the dates that matter, and five questions.
Print/save-as-PDF, copy as text, or download Markdown — and the Markdown carries
the disclaimer and the method note with it, because the brief is meant to leave
the app.

**It makes no model call.** It is a pure function of data the browser already
has, so opening it costs nothing and there is no path from it to a claim that
has not already been through the gates. The five questions are *derived*, by
ranked templates over the risks and dated duties that already exist:

| Rank | Source | Why here |
|---|---|---|
| 1 | Critical / high / medium risks | what the document does to you |
| 2 | Obligations and key dates with a deadline | what you must do, and when |
| 3 | Money clauses | what it costs you |
| 4 | Coverage gaps (max two) | what it leaves unsaid |

The questions only ever *ask* — "is this enforceable as written?" is a good
question for a lawyer and a terrible thing for this tool to assert.

Coverage gaps are a keyword check, so the question is phrased as the absence it
actually is ("the document does not appear to address this **by name**"). Gap
questions are capped at two: without a cap, a document that simply does not use
those keywords hands the reader five generic questions and none from its own
contents, which is the opposite of a tailored brief.

### Rate limiting

`RATE_LIMIT_MAX` / `RATE_LIMIT_WINDOW_MS` are enforced on both model-calling
endpoints, before the body is read, so a throttled request costs nothing — not a
parse, not an extraction, and not a model call. One limiter is shared across
both routes, because the resource being protected is model calls and those do
not care which route asked. Over the limit returns `429` with `Retry-After`.

The store is in-memory, which is correct for how this is deployed — **one
container on one VPS**. It would not be correct behind more than one replica, and
`lib/ratelimit.ts` says so rather than pretending otherwise. Restarting the
container resets the counters.

## Judging criteria coverage

Six categories, each pointing at where it is actually addressed, not just claimed.

**Code Quality** — Strict TypeScript throughout; `npm run typecheck`/`npm run lint` both
run in CI on every push (`.github/workflows/ci.yml`). One structured-call path
(`lib/llm/structured.ts`) shared by every model call rather than three copies
drifting apart. Comments explain *why*, not *what* — see `lib/deadlines.ts` or
`lib/summary/quote.ts` for the non-obvious decisions and the failure modes they
close.

**Security** — Every upload is checked by magic bytes (`lib/upload.ts`), not
filename or declared MIME type. Rate limiting on all three model-calling
endpoints, enforced before the body is even read (`lib/api-guard.ts`,
`lib/ratelimit.ts`) — `GET /api/health` was missed in an earlier pass despite
being auto-fired on every homepage load with no limit and no cache, found
during review and fixed alongside a short-lived cache for the common case
(§Efficiency). Two-layer prompt-injection defence on Q&A (`lib/injection.ts`):
a normalised pattern screen plus explicit delimited data blocks in the prompt
itself. No secret reaches the client (`GET /api/health` reports model IDs and
latency only) or the repo — `.env.local` is gitignored, verified against the
full git history, not just the current diff. Baseline response headers
(`next.config.ts`) — CSP, `X-Frame-Options`, `X-Content-Type-Options`,
`Referrer-Policy`, HSTS — confirmed missing on the live deployment with a
direct `curl -I` before adding them, since the Caddy layer in front of this
app sets them on the apex domain but never on this app's own subdomain. Set
in the app's own config instead of in Caddy, so they hold regardless of what
sits in front of it.

**Efficiency** — One model call per document, not per feature: a single
structured generation covers the summary, key terms, risks, obligations and
key dates together. A content-hash result cache (`lib/cache.ts`), keyed on the
*extracted text*, means an identical previously-analysed document skips a new
summary-model call while the one-hour in-process cache is warm — confirmed
live at ~30s on a miss versus ~0.3s on a hit for a text-layer PDF. This does
not extend to a scanned or photographed PDF's vision-transcription step:
that runs on every upload, since it produces the text the cache key is built
from, so it necessarily runs *before* a cache lookup is even possible — the
cache still saves the second (summary) call on a repeat, just not the first.
`GET /api/health` also caches its result for 30s (`healthCache` in the
route), so repeat homepage loads don't each spend a real model call the way
they did before. Deterministic work (segmentation, citation/quote
verification, date arithmetic) runs as plain synchronous code, never a model
call.

**Testing** — 296 tests across 16 files, `npm run verify` green in CI on every
push. Coverage is concentrated deliberately on the deterministic core —
segmentation, citation/quote gates, deadline arithmetic, injection screening,
the cache — where a test is cheap and a regression is otherwise invisible
until a real document trips it. Real bugs this suite caught, not hypothetical
ones: a `-1` coercing into `CLAUSE-01`, `\bdispute\b` not matching "Disputes",
and a buffer-detach race that silently produced 0-byte saved files.

**Accessibility** — Skip-to-content link, visible on keyboard focus
(`layout.tsx`, `.skip-link`). An `aria-live` announcement on the one state
transition that previously had none: analysis completing
(`SimplifyWorkbench.tsx`) — the working and error states already had
`role="status"`/`role="alert"`. Contrast checked against the surfaces actually
used, not just the page background: `--text-muted` (the footer disclaimer,
`.clause-id`, the low-severity badge, the anchor-date label — not
`.clause-chip`, which uses `--primary-color`) measured 3.12:1 (light) / 4.02:1
(dark) on `--bg-primary`, below WCAG AA's 4.5:1 floor for normal text. A first
fix measured only against that one background and missed that `.clause` and
the low-severity badge sit on `--bg-inset`, and that Voltage's worst surface
is `--bg-secondary`, not `--bg-primary` — both real failures on the elements
that actually render there. Corrected to clear the worst surface in each
theme (`globals.css`): 4.67:1 on Aurora's `--bg-inset`, 4.83:1 on Voltage's
`--bg-secondary`. The upload dropzone's real `<input type="file">` (visually
hidden, not `aria-hidden`, so it stays in the tab order) had no accessible
name — a screen-reader user tabbing to it directly, rather than through the
styled button that triggers it via ref, hit a second, generically-announced
"choose file" control. Given an `aria-label`
(`SimplifyWorkbench.tsx`). Every interactive element is a real
`<button>`/`<a>`/`<input>`, not a `<div onClick>`.

**Problem Statement Alignment** — Covers the brief's core use cases:
simplification, risk/obligation extraction with computed deadlines, grounded
Q&A, and a lawyer-prep export (see "Scope" in `BUILD_BRIEF.md` for what was
deliberately left out and why). Handles scanned and photographed documents via
vision transcription (`lib/pdf/vision.ts`), not only clean text PDFs. Never
gives legal advice or asserts enforceability — every system prompt says so
explicitly, and the UI repeats it in the footer on every page.

## Running it

```bash
cp .env.example .env.local   # then add your GEMINI_API_KEY
npm install
npm run dev                  # http://localhost:3000
```

`GET /api/health` reports the live runtime state: whether the environment
parsed, which models the key can actually reach, and which one answered. It is
the fastest way to tell whether a problem is configuration or the model.

## Environment

Server-only. `.env.local` is gitignored; `.env.example` is the template.

| Variable | Default | Notes |
|---|---|---|
| `GEMINI_API_KEY` | — | Required. Use a **paid-tier** key: on the free tier Google may use prompts to improve its products. |
| `GEMINI_MODEL` | `gemini-3.6-flash` | Primary. Pinned ID, not a `-latest` alias. |
| `GEMINI_FALLBACK_MODEL` | `gemini-3.5-flash` | One fallback tier — a different capacity pool, so a rate-limited primary still answers. |
| `MAX_UPLOAD_BYTES` | `2000000` | Upload guard. |
| `RATE_LIMIT_MAX` | `20` | Requests per window, per client. |
| `RATE_LIMIT_WINDOW_MS` | `60000` | Window length. |

**Model IDs are per-key, not a fixed list.** This is the single most surprising
thing about working with this API, so it is worth stating plainly:

- `gemini-2.5-flash` answered reliably on one key and returns
  `404 — no longer available to new users` on another. Google steers new
  accounts at the 3.x line.
- `gemini-3.7-flash` (503) and `gemini-2.5-flash-lite` (404) are listed by the
  API but not callable on the keys tried here.
- A free-tier key is capped at around 20 requests and starts returning
  `Quota exceeded for metric: ..._free_tier_requests`, which an automated
  grader will absolutely trigger.

So before changing these values, verify rather than assume:

```bash
curl "https://generativelanguage.googleapis.com/v1beta/models?key=$GEMINI_API_KEY"
```

and then call the one you intend to use. `GET /api/health` does exactly that
against the configured pair and tells you which one actually answered.

Measured wall-clock for a full simplify run on the sample agreement is roughly
**20–26s** with the primary model — it is one large structured generation, not a
chat turn, so it takes noticeably longer than a short prompt would suggest.

## Tests

`npm run test` — 296 tests across 16 files, all on deterministic code. The areas
the BUILD_BRIEF asked to prioritise are covered deliberately:

- **Segmentation** (`segment.test.ts`) — guards are tested against the literal
  strings that broke it on a real 36-page agreement: `836.1 Sq. Meters` read as
  a clause number, `1908. In accordance...` read as clause 1908, and a
  hyphenated word broken across a line.
- **Deadline arithmetic** (`deadlines.test.ts`) — month-end clamping, leap
  years, backwards offsets, and the refusal cases (no verified quote, no stated
  offset, event-relative).
- **Citation verification** (`verify.test.ts`) — canonicalisation, invention
  rejection, whole-item dropping, and the `-1` → `CLAUSE-01` coercion bug the
  tests caught.
- **Quote verification** (`quote.test.ts`) — the paraphrases a model produces
  versus a quote reassembled out of words that are in the clause but not in that
  order.
- **Risks & obligations** (`risks.test.ts`) — severity vocabulary, offset
  vocabulary, the four deadline bases, and the end-to-end chain from model
  output to a computed date.
- **Injection screen** (`injection.test.ts`) — 12 legitimate questions that must
  pass, 22 attempts that must not, and the zero-width and full-width evasions.
- **Grounded answers** (`answer.test.ts`) — the all-or-nothing citation rule and
  the "not in the document" path, driven by an injected generator. A rule that
  only holds when the live model happens to misbehave is not a rule, so these do
  not depend on provoking an API.
- **Rate limiter** (`ratelimit.test.ts`) — window boundaries, per-key isolation,
  and the bounded-map behaviour that stops a flood of source addresses becoming
  the denial of service itself.
- **Brief questions** (`questions.test.ts`) — ranking, deduplication, the
  two-gap cap, and the plural/derived word forms that a first cut missed
  (`\bdispute\b` does not match "Disputes").
- **Brief assembly** (`brief.test.ts`) — the whole artifact and its Markdown,
  including that an empty section says so rather than leaving a bare heading.
- **Upload validation** (`upload.test.ts`) — including a PNG renamed to `.pdf`,
  checked against magic bytes rather than its name.
- **Sample integrity** (`rent-agreement.test.ts`) — the bundled PDF still yields
  all 18 clause markers after extraction, and the embedded copy still matches
  the `.txt` source.
UI components are not unit-tested. There is not time to do it properly, and a
shallow render test of a client component earns nothing that the browser check
does not.


## Design

Follows the Govu Design System: two looks, one switch, wired through
`data-theme` on `<html>` — **Aurora** (light: white, blue, orange) and
**Voltage** (dark: black, yellow, green). Both ship, the toggle persists to
`localStorage`, and an inline pre-paint script means the page never flashes the
wrong one. Components are built from tokens only; `src/styles/govu-tokens.css`
is an unmodified copy of the canonical token file.
